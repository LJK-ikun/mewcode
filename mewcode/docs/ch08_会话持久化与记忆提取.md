# CH08: 会话持久化与记忆提取

## 从一个真实场景说起

你正在和 AI 调试一个复杂的 Bug，花了 2 小时，终于找到了问题所在。突然：

```
电脑死机...
重启后，所有对话历史都丢失了！
```

**更糟糕的是，第二天你继续工作：**

```
你: 继续昨天的 Bug 修复工作
AI: 抱歉，我不知道你昨天在做什么...
```

**一周后，你又遇到类似的问题：**

```
你: 帮我配置 PostgreSQL
AI: 好的，应该用哪个版本？
你: 我上次不是说过用 15 吗？
AI: 抱歉，我不记得了...
```

这就是为什么需要**会话持久化与记忆提取**：

1. **会话持久化** → 对话可以保存和恢复，永不丢失
2. **记忆提取** → 提取关键信息，跨会话共享
3. **智能召回** → 在需要的时候自动加载相关记忆

---

## 核心挑战：如何在保存和召回之间平衡？

### 挑战 1：什么值得记住？什么可以忘记？

```
对话历史：
[1] User: 你好                     ← 不重要，可以忘记
[2] Assistant: 你好！               ← 不重要
[3] User: 我喜欢用 4 空格缩进       ← 重要！用户偏好
[4] User: 项目用 PostgreSQL 15     ← 重要！项目知识
[5] User: 帮我读取 config.yaml     ← 不重要，一次性任务
[6] User: 不要用 var，用 const     ← 重要！纠正反馈
```

**如何区分重要和不重要？**

### 挑战 2：如何组织记忆？

```
错误的方式（流水账）：
- 用户说喜欢 4 空格
- 用户说项目用 PostgreSQL
- 用户说不要用 var
- 用户说喜欢简洁代码
- 用户说 PostgreSQL 版本是 15
...

问题：
- 没有分类，查找困难
- 信息重复（PostgreSQL 说了两次）
- 没有优先级
```

**正确的方式（结构化）：**

```
### 用户偏好
- 缩进使用 4 空格，不用 Tab
- 代码风格偏好简洁，避免冗余

### 纠正反馈
- 不要使用 var 声明变量，优先使用 const

### 项目知识
- 数据库：PostgreSQL 15

### 参考资料
- API 文档: https://example.com/docs
```

### 挑战 3：何时召回记忆？

```
场景 1：用户说"帮我配置数据库"
    → 应该召回"项目知识：PostgreSQL 15"

场景 2：用户说"写一个函数"
    → 应该召回"用户偏好：4 空格缩进"

场景 3：用户说"今天天气怎么样"
    → 不需要召回任何记忆
```

**如何判断哪些记忆相关？**

## 系统的解决方案：双层记忆体系

```
Layer 1: 会话持久化（Session Storage）
    ├─ 短期记忆（单次会话）
    ├─ 完整对话历史
    └─ 可恢复、可列表、可删除

Layer 2: 记忆提取（Memory Extraction）
    ├─ 长期记忆（跨会话）
    ├─ 结构化存储（4 种类型）
    └─ 智能召回（相关性匹配）

记忆类型：
    ├─ user: 用户偏好和习惯
    ├─ feedback: 纠正和反馈
    ├─ project: 项目知识
    └─ reference: 参考资料

记忆范围：
    ├─ User-level: ~/.mewcode/memory/
    └─ Project-level: .mewcode/memory/
```

## Layer 1: 会话持久化 - 保存与恢复

### 会话元数据（SessionMeta）

**问题：如何快速列出所有会话？**

```python
# memory/session.py:318-326
@dataclass
class SessionMeta:
    id: str                      # session_20240924_142530_a7f3
    title: str = ""              # 第一条用户消息（前 50 字符）
    summary: str = ""            # LLM 生成的摘要
    message_count: int = 0       # 消息数量
    total_tokens: int = 0        # 累计 token 用量
    created_at: datetime         # 创建时间
    last_active: datetime        # 最后活跃时间（用于排序）
```

**存储位置**：

```
.mewcode/sessions/
├── session_20240924_142530_a7f3.jsonl  ← 对话记录
├── session_20240924_142530_a7f3.meta   ← 元数据
├── session_20240924_150830_b2c1.jsonl
├── session_20240924_150830_b2c1.meta
...
```

**为什么分开存储？**

- **快速列表**：读取 `.meta` 就能列出所有会话，不需要解析完整 `.jsonl`
- **增量更新**：只更新元数据，不用重写整个对话文件
- **容错性**：元数据损坏不影响对话数据

### 会话 ID 生成

**要求：唯一、可读、可排序**

```python
# memory/session.py:464-467
def _generate_session_id() -> str:
    now = datetime.now()
    suffix = "".join(random.choices(string.ascii_lowercase + string.digits, k=4))
    return f"session_{now.strftime('%Y%m%d_%H%M%S')}_{suffix}"
```

**生成示例**：

```
2024-09-24 14:25:30 → session_20240924_142530_a7f3
2024-09-24 14:25:30 → session_20240924_142530_k9m2  (同一秒的另一个)
2024-09-24 15:08:30 → session_20240924_150830_b2c1
```

**设计要点**：

- **时间戳前缀**：`YYYYMMDD_HHMMSS` → 自然排序 = 时间排序
- **随机后缀**：4 字符 → 避免同一秒内的 ID 冲突
- **可读性**：不是纯 UUID，人类可以识别时间

### 创建会话

```python
# memory/session.py:476-488
def create(self) -> Session:
    session_id = _generate_session_id()
    jsonl_path = self._sessions_dir / f"{session_id}.jsonl"
    
    # 1. 创建元数据
    meta = SessionMeta(id=session_id)
    meta.save(self._sessions_dir / f"{session_id}.meta")
    
    # 2. 以追加模式打开 JSONL 文件
    file = open(jsonl_path, "a", encoding="utf-8")
    
    return Session(
        session_id=session_id,
        file=file,
        meta=meta,
        sessions_dir=self._sessions_dir,
    )
```

**关键设计**：

- **追加模式 "a"**：只能在文件末尾写入，不会覆盖已有内容
- **立即创建元数据**：即使对话为空，也能在列表中显示
- **返回 Session 对象**：持有文件句柄，可以持续写入

```python
def append(self, message: Message) -> None:
    # 1. 将 Message 转换为 SessionRecord 列表
    records = SessionRecord.from_message(message)
    
    # 2. 逐条写入 JSONL
    for record in records:
        self._file.write(record.to_jsonl() + "\n")
    self._file.flush()  # 立即刷盘
    
    # 3. 更新元数据
    self.meta.message_count += 1
    self.meta.last_active = datetime.now(timezone.utc)
    
    # 4. 自动提取 title（从第一条用户消息）
    if not self.meta.title and message.role == "user" and message.content:
        self.meta.title = message.content[:TITLE_MAX_LENGTH]
    
    # 5. 保存元数据
    self.meta.save(self._sessions_dir / f"{self.session_id}.meta")
```

### 恢复会话

```python
# memory/session.py:500-548
def resume(self, session_id: str) -> ResumeResult | None:
    jsonl_path = self._sessions_dir / f"{session_id}.jsonl"
    meta_path = self._sessions_dir / f"{session_id}.meta"
    
    if not jsonl_path.exists():
        return None
    
    # 1. 加载元数据
    meta = SessionMeta.load(meta_path)
    if meta is None:
        return None
    
    # 2. 读取所有 record
    records: list[SessionRecord] = []
    with open(jsonl_path, encoding="utf-8") as f:
        for line in f:
            line = line.strip()
            if not line:
                continue
            record = SessionRecord.from_jsonl(line)
            if record is not None:
                records.append(record)
    
    # 3. 重建压缩后的状态（从最后一个 COMPACT_BOUNDARY 开始）
    last_boundary = -1
    for i, rec in enumerate(records):
        if rec.type == RecordType.COMPACT_BOUNDARY:
            last_boundary = i
    if last_boundary >= 0:
        records = records[last_boundary:]  # 只保留 boundary 之后的
    
    # 4. 校验消息链完整性（确保 tool_use ↔ tool_result 配对）
    valid_count = validate_message_chain(records)
    records = records[:valid_count]
    
    # 5. 转换为 Message
    messages = records_to_messages(records)
    
    # 6. 重新打开文件用于追加
    file = open(jsonl_path, "a", encoding="utf-8")
    session = Session(
        session_id=session_id,
        file=file,
        meta=meta,
        sessions_dir=self._sessions_dir,
    )
    
    return ResumeResult(
        session=session,
        messages=messages,
        last_active=meta.last_active,
    )
```

**关键步骤**：

1. **加载元数据**：验证会话是否存在
2. **解析 JSONL**：逐行读取，容错处理损坏的行
3. **从 COMPACT_BOUNDARY 开始**：跳过已压缩的前缀（参见 CH07）
4. **校验完整性**：截断不完整的工具调用
5. **转换为 Message**：重建对话历史
6. **追加模式重新打开**：可以继续写入新消息

### 删除会话

```python
# memory/session.py:550-561
def delete(self, session_id: str) -> bool:
    jsonl_path = self._sessions_dir / f"{session_id}.jsonl"
    meta_path = self._sessions_dir / f"{session_id}.meta"
    
    deleted = False
    if jsonl_path.exists():
        jsonl_path.unlink()
        deleted = True
    if meta_path.exists():
        meta_path.unlink()
        deleted = True
    return deleted
```

**幂等性**：

- 文件不存在时不会报错
- 返回 `True` 表示至少删除了一个文件
- 返回 `False` 表示会话不存在

### 清理过期会话

```python
# memory/session.py:563-573
def cleanup(self, max_age_days: int = DEFAULT_MAX_AGE_DAYS) -> int:
    """删除超过 max_age_days 未活跃的会话"""
    cutoff = datetime.now(timezone.utc) - timedelta(days=max_age_days)
    removed = 0
    
    for meta_path in list(self._sessions_dir.glob("*.meta")):
        meta = SessionMeta.load(meta_path)
        if meta is not None and meta.last_active < cutoff:
            self.delete(meta.id)
            removed += 1
    
    return removed
```

### 自动记忆提取（MemoryManager）

**触发时机**：

**提取逻辑**：

```python
# memory/auto_memory.py:94-148
async def extract(
    self,
    client: Any,
    conversation: ConversationManager,
    protocol: str,
) -> None:
    # 1. 加载当前记忆
    current_memories = self.load()
    
    # 2. 获取新增对话（自上次提取以来）
    recent = conversation.history[self._last_extraction_msg_count:]
    if not recent:
        return
    
    # 3. 构建对话摘要
    conv_lines: list[str] = []
    for msg in recent:
        if msg.role == "user" and msg.content:
            conv_lines.append(f"用户: {msg.content}")
        elif msg.role == "assistant" and msg.content:
            conv_lines.append(f"助手: {msg.content}")
    
    if not conv_lines:
        return
    
    # 4. 构建提取 prompt
    prompt = (
        f"{MEMORY_EXTRACTION_PROMPT}\n\n"
        f"## 当前 memories.md\n"
        f"{current_memories if current_memories else '(空)'}\n\n"
        f"## 最近对话\n"
        f"{chr(10).join(conv_lines)}\n\n"
        f"请输出更新后的完整 memories.md 内容。"
    )
    
    # 5. 调用 LLM 生成更新后的记忆
    extract_conv = ConversationManager()
    extract_conv.history = [Message(role="user", content=prompt)]
    
    collected = ""
    async for event in client.stream(extract_conv, system="你是一个记忆提取助手。"):
        if isinstance(event, TextDelta):
            collected += event.text
    
    # 6. 更新最后提取位置
    self._last_extraction_msg_count = len(conversation.history)
    
    # 7. 写入记忆文件
    self._write_memories(collected)
```

**关键设计点**：

- **增量提取**：只处理新增对话，不重复处理已提取的
- **保留上下文**：传入当前记忆，让 LLM 知道已有什么
- **完整输出**：LLM 输出完整的 memories.md，不是 diff

### 记忆提取 Prompt

```python
# memory/auto_memory.py:11-37
MEMORY_EXTRACTION_PROMPT = """\
你是一个记忆提取助手。分析下面的对话，提取值得长期记忆的信息，更新 memories.md。

分类规则：
- **用户偏好**：用户的编码习惯和风格要求（如缩进、命名规范、语言偏好）
- **纠正反馈**：用户明确指出的错误和正确做法
- **项目知识**：当前项目的具体技术信息（技术栈、目录结构、部署方式）
- **参考资料**：外部链接和文档地址

规则：
1. 已有相同含义的条目不要重复添加
2. 没有值得记忆的内容，该分类下留空（不要写任何条目，不要写占位符）
3. 每条记忆用一行 `- ` 开头，必须是具体内容，不要用 `...` 占位
4. 输出完整的 memories.md 内容，包含所有四个分类标题

输出格式（严格遵守，没有内容的分类下不写任何条目）：
### 用户偏好
- 用户偏好简洁代码风格

### 纠正反馈

### 项目知识
- 项目使用 PostgreSQL 15

### 参考资料

不要输出任何其他内容，不要调用任何工具。"""
```

**为什么需要这么详细的 Prompt？**

| 问题 | 解决方案 |
|------|----------|
| LLM 输出格式不统一 | 严格指定输出格式 |
| LLM 添加无用信息（如"暂无"） | 明确禁止占位符 |
| LLM 重复已有信息 | 传入当前记忆，要求去重 |
| LLM 调用工具 | 明确禁止工具调用 |
| 分类不明确 | 详细解释每个分类的含义 |

### 记忆分类与写入

```python
# memory/auto_memory.py:150-183
def _write_memories(self, content: str) -> None:
    user_sections: list[str] = []       # 用户级记忆
    project_sections: list[str] = []    # 项目级记忆
    
    current_header = ""
    current_lines: list[str] = []
    
    # 1. 解析 LLM 输出，按标题分组
    for line in content.split("\n"):
        if line.startswith("### "):
            if current_header:
                self._assign_section(
                    current_header, current_lines, user_sections, project_sections
                )
            current_header = line
            current_lines = []
        else:
            current_lines.append(line)
    
    if current_header:
        self._assign_section(current_header, current_lines, user_sections, project_sections)
    
    # 2. 写入用户级记忆
    if user_sections:
        self._user_path.parent.mkdir(parents=True, exist_ok=True)
        self._user_path.write_text(
            "\n".join(user_sections).strip() + "\n", encoding="utf-8"
        )
    
    # 3. 写入项目级记忆
    if project_sections:
        self._project_path.parent.mkdir(parents=True, exist_ok=True)
        self._project_path.write_text(
            "\n".join(project_sections).strip() + "\n", encoding="utf-8"
        )
```

```markdown
  type: project
```

**Frontmatter 字段**：

```python

class MemoryHeader:
    filename: str      # relative/path/to/memory.md
```

- **相关性匹配**：LLM 根据 description 判断是否相关

### 扫描记忆文件

```python
def scan_memory_files(memory_dir: Path, scope: str) -> list[MemoryHeader]:
    """扫描目录中的所有 .md 文件（排除 MEMORY.md）"""
    if not memory_dir.is_dir():
        return []
    
    # 1. 递归查找所有 .md 文件
    md_files: list[Path] = []
    try:
        for fp in memory_dir.rglob("*.md"):
            if fp.is_file() and fp.name != ENTRYPOINT_NAME:
                md_files.append(fp)
    except OSError:
        return []
    
    # 2. 读取每个文件的 frontmatter
    results: list[MemoryHeader] = []
    for fp in md_files:
        hdr = _read_memory_header(fp, memory_dir, scope)
        if hdr is not None:
            results.append(hdr)
    
    # 3. 按修改时间倒序排列（最新的优先）
    results.sort(key=lambda h: h.mtime_ms, reverse=True)
    
    # 4. 限制数量（防止文件过多）
    if len(results) > MAX_MEMORY_FILES:
        results = results[:MAX_MEMORY_FILES]
    
    return results
```

- **相关性考虑**：记忆太多，召回精度下降
- **实际够用**：200 个结构化记忆已经很多了

### Frontmatter 解析

```python
# memory/recall.py:104-135
def parse_frontmatter(content: str) -> dict[str, str]:
    """提取 YAML frontmatter 中的 name/description/type"""
    # 1. 匹配 frontmatter 块（--- 开头和结尾）
    m = FRONTMATTER_RE.match(content)
    if not m:
        return {"name": "", "description": "", "type": ""}
    
    block = m.group(1)
    result: dict[str, str] = {"name": "", "description": "", "type": ""}
    
    # 2. 逐行解析 key: value
    for line in block.split("\n"):
        colon = line.find(":")
        if colon < 0:
            continue
        
        key = line[:colon].strip()
        val = line[colon + 1:].strip()
        
        # 3. 去除引号
        if len(val) >= 2 and (
            (val.startswith('"') and val.endswith('"')) or
            (val.startswith("'") and val.endswith("'"))
        ):
            val = val[1:-1]
        
        # 4. 提取已知字段
        if key == "name":
            result["name"] = val
        elif key == "description":
            result["description"] = val
        elif key == "type":
            if val in VALID_TYPES:  # {"user", "feedback", "project", "reference"}
                result["type"] = val
    
    return result
```


**为什么？**

- **性能优化**：不需要读取整个文件
- **足够了**：frontmatter 通常在前几行
- **容错**：即使文件很大，也不会卡住

### 相关性匹配（LLM 选择器）

**核心思想**：让 LLM 根据用户查询选择相关的记忆

```python
# memory/recall.py:233-274
async def find_relevant_memories(
    query: str,                          # 用户查询
    user_mem_dir: Path | None,           # 用户级记忆目录
    project_mem_dir: Path | None,        # 项目级记忆目录
    recent_tools: list[str] | None,      # 最近使用的工具
    already_surfaced: set[str] | None,   # 已加载的记忆（避免重复）
    selector: SelectorFn,                # LLM 选择器函数
) -> list[RelevantMemory]:
    # 1. 扫描两个目录
    all_headers: list[MemoryHeader] = []
    if user_mem_dir is not None:
        all_headers.extend(scan_memory_files(user_mem_dir, "user"))
    if project_mem_dir is not None:
        all_headers.extend(scan_memory_files(project_mem_dir, "project"))
    
    # 2. 过滤已加载的记忆
    surfaced = already_surfaced or set()
    candidates = [m for m in all_headers if m.file_path not in surfaced]
    if not candidates:
        return []
    
    # 3. 调用 LLM 选择相关记忆（最多 5 个）
    selected_filenames = await _select_relevant_memories(
        query, candidates, recent_tools, selector
    )
    
    # 4. 根据文件名查找对应的 MemoryHeader
    by_key: dict[str, MemoryHeader] = {}
    for m in candidates:
        by_key[m.file_path] = m
        by_key.setdefault(m.filename, m)
    
    result: list[RelevantMemory] = []
    for fn in selected_filenames:
        m = by_key.get(fn)
        if m is not None:
            result.append(RelevantMemory(path=m.file_path, mtime_ms=m.mtime_ms))
    
    return result
```

### 选择器调用

```python
# memory/recall.py:277-310
async def _select_relevant_memories(
    query: str,
    memories: list[MemoryHeader],
    recent_tools: list[str] | None,
    selector: SelectorFn,
) -> list[str]:
    """调用 LLM 选择相关记忆，返回文件名列表"""
    valid_filenames = {m.filename for m in memories}
    
    # 1. 格式化记忆清单
    manifest = format_memory_manifest(memories)
    
    # 2. 添加最近使用的工具信息
    tools_section = ""
    if recent_tools:
        tools_section = "\n\nRecently used tools: " + ", ".join(recent_tools)
    
    # 3. 构建用户消息
    user_message = f"Query: {query}\n\nAvailable memories:\n{manifest}{tools_section}"
    
    # 4. 调用 LLM
    try:
        raw = await selector(SELECTOR_SYSTEM_PROMPT, user_message)
    except Exception:
        return []  # 容错：选择失败不影响主流程
    
    # 5. 提取 JSON 对象
    clean = _extract_json_object(raw)
    if not clean:
        return []
    
    # 6. 解析 JSON，返回有效的文件名
    try:
        parsed = json.loads(clean)
        arr = parsed.get("selected_memories", [])
        if not isinstance(arr, list):
            return []
        return [f for f in arr if isinstance(f, str) and f in valid_filenames]
    except (json.JSONDecodeError, AttributeError):
        return []
```

**容错设计**：

- **选择失败 → 返回空列表**：不影响主流程
- **JSON 解析失败 → 返回空列表**：LLM 输出不规范时降级
- **文件名校验**：只返回存在的文件名

```python
# memory/recall.py:210-227
def format_memory_manifest(memories: list[MemoryHeader]) -> str:
    """将记忆列表格式化为文本清单"""
    if not memories:
        return ""
    
    lines: list[str] = []
    for m in memories:
        # 1. 作用域标签
        scope_tag = f"[{m.scope}-scope] " if m.scope else ""
        
        # 2. 类型标签
        type_tag = f"[{m.type}] " if m.type else ""
        
        # 3. 时间戳
        ts = datetime.fromtimestamp(
            m.mtime_ms / 1000, tz=timezone.utc
        ).strftime("%Y-%m-%dT%H:%M:%S.") + f"{m.mtime_ms % 1000:03d}Z"
        
        # 4. 路径
        path = m.file_path if m.file_path else m.filename
        
        # 5. 描述
        if m.description:
            lines.append(f"- {scope_tag}{type_tag}{path} ({ts}): {m.description}")
        else:
            lines.append(f"- {scope_tag}{type_tag}{path} ({ts})")
    
    return "\n".join(lines)
```

```python
def memory_age_days(mtime_ms: int) -> int:
    """计算记忆的年龄（天数）"""
    d = (int(time.time() * 1000) - mtime_ms) // 86_400_000

    if d == 1:

    return f"{d} days ago"
```

**问题：指令文件太长，难以维护**

**处理逻辑**：

```python
# memory/instructions.py:13-51
def process_includes(
    content: str,
    base_dir: Path,
    project_root: Path,
    depth: int = 0,
) -> str:
    # 1. 防止无限递归
    if depth >= MAX_INCLUDE_DEPTH:
        return content
    
    resolved_root = project_root.resolve()
    lines = content.split("\n")
    result: list[str] = []
    
    for line in lines:
        stripped = line.strip()
        
        # 2. 不是 @include 指令，直接保留
        if not stripped.startswith(INCLUDE_PREFIX):
            result.append(line)
            continue
        
        # 3. 提取路径
        rel_path = stripped[len(INCLUDE_PREFIX):].strip()
        abs_path = (base_dir / rel_path).resolve()
        
        # 4. 安全检查：路径必须在项目内
        try:
            abs_path.relative_to(resolved_root)
        except ValueError:
            result.append("<!-- @include blocked: path outside project -->")
            continue
        
        # 5. 文件必须存在
        if not abs_path.exists() or not abs_path.is_file():
            result.append("<!-- @include skipped: file not found -->")
            continue
        
        # 6. 读取并递归处理
        included = abs_path.read_text(encoding="utf-8")
        processed = process_includes(included, abs_path.parent, project_root, depth + 1)
        result.append(processed)
    
    return "\n".join(result)
```

```python

```

**为什么需要限制深度？**

```

            @include c.md
                @include d.md
                    @include e.md

```

**防止**：

- **无限递归**：a.md → b.md → a.md → ...
- **深度爆炸**：文件嵌套太深，难以理解
- **性能问题**：读取太多文件

## 代码亮点：设计模式与最佳实践

### 亮点 1：会话持久化的容错设计

```python
# ✅ 好做法：逐行容错
records: list[SessionRecord] = []
with open(jsonl_path, encoding="utf-8") as f:
    for line in f:
        record = SessionRecord.from_jsonl(line)
        if record is not None:  # 跳过损坏的行
            records.append(record)

# ❌ 坏做法：一行损坏，全部丢失
records = [SessionRecord.from_jsonl(line) for line in f]
```

**好处**：

- **部分恢复**：损坏的行不影响其他行
- **易调试**：可以看到损坏的具体位置
- **容灾**：手动编辑 JSONL 时不会全盘崩溃

### 亮点 2：记忆提取的增量处理

```python
# ✅ 好做法：只处理新增对话
self._last_extraction_msg_count = 0  # 初始化

async def extract(...):
    recent = conversation.history[self._last_extraction_msg_count:]
    if not recent:
        return  # 没有新消息，跳过
    
    # 处理新消息...
    
    self._last_extraction_msg_count = len(conversation.history)

# ❌ 坏做法：每次处理全部对话
async def extract(...):
    for msg in conversation.history:  # 重复处理已提取的
        ...
```

**好处**：

- **性能优化**：只处理新增部分
- **减少成本**：不重复调用 LLM
- **避免重复**：不会重复提取同样的记忆

### 亮点 3：LLM 选择器的容错降级

```python
# ✅ 好做法：选择失败不影响主流程
try:
    selected = await find_relevant_memories(...)
except Exception:
    selected = []  # 降级为空列表

# 主流程继续，只是没有记忆加载
conversation.history.append(...)

# ❌ 坏做法：选择失败导致崩溃
selected = await find_relevant_memories(...)  # 异常传播
```

**好处**：

- **可用性优先**：记忆召回是增强功能，不是核心功能
- **优雅降级**：即使记忆系统故障，对话仍能继续
- **用户无感**：用户不会因为记忆问题而无法使用

### 亮点 4：占位符过滤的严格性

```python
# ✅ 好做法：严格过滤占位符
@staticmethod
def _is_placeholder(line: str) -> bool:
    stripped = line.strip().lstrip("- ").strip()
    return stripped in {"", "...", "…", "无", "暂无", "N/A"}

real_lines = [l for l in lines if not _is_placeholder(l)]
if not real_lines:
    return  # 没有真实内容，跳过整个分类

# ❌ 坏做法：保留占位符
for line in lines:
    file.write(line)  # "- 暂无" 也被写入
```

**好处**：

- **清洁数据**：记忆文件没有无用内容
- **提升质量**：LLM 看到的都是有价值的信息
- **减少噪音**：避免 "暂无" 干扰 LLM 判断

### 亮点 5：@include 的安全限制

```python
# ✅ 好做法：多层安全检查
# 1. 深度限制
if depth >= MAX_INCLUDE_DEPTH:
    return content

# 2. 路径限制
try:
    abs_path.relative_to(project_root)
except ValueError:
    return "<!-- blocked: path outside project -->"

# 3. 文件存在性
if not abs_path.exists():
    return "<!-- skipped: file not found -->"

# ❌ 坏做法：无限制包含
included = abs_path.read_text()  # 可能读取任意文件
return included
```

**好处**：

- **防止路径遍历**：不能包含项目外的文件
- **防止无限递归**：深度限制 5 层
- **容错处理**：文件不存在时不崩溃

### 亮点 6：记忆年龄的可读性

```python
# ✅ 好做法：人类可读
def memory_age(mtime_ms: int) -> str:
    d = memory_age_days(mtime_ms)
    if d == 0:
        return "today"
    if d == 1:
        return "yesterday"
    return f"{d} days ago"

# 显示: Memory: config.md (saved today)

# ❌ 坏做法：显示时间戳
# 显示: Memory: config.md (saved 1727184330123)
```

**好处**：

- **易读**：用户一眼看出记忆的新鲜度
- **自然**：符合人类的时间感知
- **国际化友好**：易于翻译

### 亮点 7：新鲜度警告的时机

```python
# ✅ 好做法：只警告旧记忆
def memory_freshness_text(mtime_ms: int) -> str:
    d = memory_age_days(mtime_ms)
    if d <= 1:
        return ""  # 今天和昨天不警告
    return f"This memory is {d} days old. ..."

# ❌ 坏做法：总是警告
def memory_freshness_text(mtime_ms: int) -> str:
    return "This memory may be outdated."
```

**好处**：

- **减少噪音**：新记忆不需要警告
- **精准提示**：只在必要时提醒
- **信任平衡**：新记忆可信，旧记忆需验证

## 总结

双层记忆体系解决了什么问题：

1. **Layer 1 (会话持久化)**：保存和恢复完整对话历史
2. **Layer 2 (记忆提取)**：提取关键信息，跨会话共享
3. **Layer 3 (智能召回)**：根据相关性自动加载记忆

**代码亮点**：

- ✨ **容错设计**：JSONL 逐行解析，损坏不影响全局
- ✨ **增量处理**：只处理新增对话，避免重复
- ✨ **优雅降级**：记忆系统故障不影响主流程
- ✨ **严格过滤**：占位符不污染记忆文件
- ✨ **安全限制**：@include 防止路径遍历
- ✨ **可读性优先**：时间显示符合人类习惯
- ✨ **精准警告**：只在必要时提示记忆陈旧

核心原则：

- **持久化优先**：对话永不丢失
- **结构化存储**：记忆分类清晰
- **智能召回**：相关性匹配
- **容错降级**：出错不崩溃
