# CH04: 系统提示词组装管理

## 从一个简单问题说起

当你启动 AI Agent，第一次发送请求时，系统会构建一个"系统提示词"（system prompt）发给 AI：

```
你是 MewCode，一个 AI 编程助手...
你可以使用以下工具：ReadFile, WriteFile, Bash...
当前工作目录：/home/user/project
当前时间：2024-03-15
用户自定义指令：代码风格使用 snake_case...
已激活的技能：/review - 代码审查技能...
记忆系统：用户是一名资深 Python 开发者...
```

**问题来了**：

1. 这些内容从哪里来？
2. 为什么有的内容必须在最前面，有的在最后？
3. 如何灵活组合不同的模块？
4. Plan 模式下提示词有什么不同？

这就是**系统提示词组装管理**要解决的问题。

---

## 核心挑战：模块化 + 优先级

### 挑战 1：提示词由多个模块组成

```
身份定义 (Identity)
    "你是 MewCode，一个 AI 编程助手..."

系统说明 (System)
    "工具执行基于权限设置..."

任务指导 (DoingTasks)
    "用户主要请求软件工程任务..."

环境信息 (Environment)
    "工作目录：/home/user/project"

用户指令 (CustomInstructions)
    "代码风格：snake_case..."

技能列表 (Skills)
    "可用技能：/review, /test..."

记忆系统 (Memory)
    "用户信息：资深 Python 开发者..."
```

### 挑战 2：顺序很重要

```
✅ 正确顺序：
身份定义 → 系统说明 → 任务指导 → 环境信息 → 用户指令 → 技能 → 记忆

❌ 错误顺序：
记忆 → 身份定义 → 用户指令 → 系统说明
（AI 可能优先遵循记忆中的旧指令，忽略新的系统说明）
```

### 挑战 3：动态组合

```
场景 1：普通模式
    需要：身份 + 系统 + 任务 + 环境

场景 2：有用户自定义指令
    需要：身份 + 系统 + 任务 + 环境 + 用户指令

场景 3：激活了技能
    需要：身份 + 系统 + 任务 + 环境 + 用户指令 + 技能

场景 4：Plan 模式
    需要：身份 + 系统 + 任务 + Plan 专用提示 + 环境
```

## 第一步：PromptSection - 提示词的"积木"

### 最简单的数据结构

```python
@dataclass
class PromptSection:
    name: str         # 模块名称
    priority: int     # 优先级（数字越小越靠前）
    content: str      # 实际内容
```

### 动态生成的模块

```python
def environment_section(work_dir: str) -> PromptSection:
    """动态生成环境信息模块"""
    lines = [
        "# Environment",
        f" - Working directory: {work_dir}",
        f" - Platform: {platform.system()} {platform.release()}",
        f" - Date: {datetime.now().strftime('%Y-%m-%d')}",
    ]
    return PromptSection(
        name="Environment",
        priority=70,  # 优先级 70
        content="\n".join(lines)
    )

# 实际使用
section = environment_section("/home/user/project")
# 生成:
# # Environment
#  - Working directory: /home/user/project
#  - Platform: Linux 5.15.0
#  - Date: 2024-03-15
```

## 第二步：PromptBuilder - 组装引擎

### 核心思想：收集 + 排序 + 拼接

```python
class PromptBuilder:
    def __init__(self):
        self._sections: list[PromptSection] = []
    
    def add(self, section: PromptSection) -> PromptBuilder:
        """添加一个模块（链式调用）"""
        self._sections.append(section)
        return self
    
    def build(self) -> str:
        """构建最终的提示词"""
        # 步骤 1: 按优先级排序
        self._sections.sort(key=lambda s: s.priority)
        
        # 步骤 2: 提取内容并过滤空白
        parts = [s.content.strip() for s in self._sections if s.content.strip()]
        
        # 步骤 3: 用两个换行符连接
        return "\n\n".join(parts)
```

### 使用示例

```python
# 构建一个基础的系统提示词
builder = PromptBuilder()
builder.add(IDENTITY_SECTION)       # priority=0
builder.add(SYSTEM_SECTION)         # priority=10
builder.add(DOING_TASKS_SECTION)    # priority=20
builder.add(environment_section("/home/user/project"))  # priority=70

prompt = builder.build()

# 结果（自动按优先级排序）:
"""
You are MewCode, an AI programming assistant...

# System
 - All text you output outside of tool use is displayed to the user...

# Doing tasks
 - The user will primarily request software engineering tasks...

# Environment
 - Working directory: /home/user/project
 - Platform: Linux 5.15.0
 - Date: 2024-03-15
"""
```

### 链式调用的优雅

```python
# 方式 1: 一次一行
builder = PromptBuilder()
builder.add(IDENTITY_SECTION)
builder.add(SYSTEM_SECTION)
builder.add(DOING_TASKS_SECTION)

# 方式 2: 链式调用（更紧凑）
prompt = (
    PromptBuilder()
    .add(IDENTITY_SECTION)
    .add(SYSTEM_SECTION)
    .add(DOING_TASKS_SECTION)
    .build()
)
```

## 第三步：build_system_prompt - 统一入口

### 核心函数

```python
def build_system_prompt(
    hook_prompts: list[str] | None = None,
    coordinator_mode: bool = False,
    agent_catalog: list[tuple[str, str]] | None = None,
    custom_instructions: str = "",
    skill_section: str = "",
    memory_section: str = "",
    work_dir: str = ".",
) -> str:
    """构建完整的系统提示词"""
    
    # 特殊模式：Team Coordinator
    if coordinator_mode:
        from mewcode.teams.coordinator import get_coordinator_system_prompt
        return get_coordinator_system_prompt(agent_catalog=agent_catalog)
    
    # 标准模式：逐步添加模块
    b = PromptBuilder()
    b.add(IDENTITY_SECTION)              # priority=0
    b.add(SYSTEM_SECTION)                # priority=10
    b.add(DOING_TASKS_SECTION)           # priority=20
    b.add(EXECUTING_ACTIONS_SECTION)     # priority=30
    b.add(USING_TOOLS_SECTION)           # priority=40
    b.add(TONE_STYLE_SECTION)            # priority=50
    b.add(TEXT_OUTPUT_SECTION)           # priority=60
    b.add(environment_section(work_dir)) # priority=70
    
    # 可选模块 1: 用户自定义指令
    if custom_instructions:
        b.add(PromptSection(
            name="CustomInstructions",
            priority=80,
            content=f"# Project Instructions\n\n{custom_instructions}",
        ))
    
    # 可选模块 2: 技能列表
    if skill_section:
        b.add(PromptSection(
            name="Skills",
            priority=90,
            content=skill_section
        ))
    
    # 可选模块 3: 记忆系统
    if memory_section:
        b.add(PromptSection(
            name="Memory",
            priority=95,
            content=memory_section
        ))
    
    result = b.build()
    
    # 附加：Hook 注入的上下文（不参与排序）
    if hook_prompts:
        result += "\n\n# Hook Injected Context\n" + "\n".join(hook_prompts)
    
    return result
```

### 优先级设计

```
0   - Identity (身份定义) - 必须最先，确立 AI 的角色
10  - System (系统说明) - 基础规则
20  - DoingTasks (任务指导) - 如何完成任务
30  - ExecutingActions (执行指导) - 如何安全执行
40  - UsingTools (工具使用) - 工具使用规范
50  - ToneStyle (语气风格) - 交互风格
60  - TextOutput (文本输出) - 输出格式
70  - Environment (环境信息) - 运行环境
80  - CustomInstructions (用户指令) - 项目特定规则
90  - Skills (技能列表) - 可用技能
95  - Memory (记忆系统) - 用户偏好和历史

Hook Injected Context - 最后附加（不参与排序）
```

### 实际调用示例

```python
# 场景 1: 最简单的启动
prompt = build_system_prompt(work_dir="/home/user/project")
# 只包含 7 个核心模块

# 场景 2: 加载用户自定义指令
prompt = build_system_prompt(
    work_dir="/home/user/project",
    custom_instructions="使用 snake_case 命名\ncommit message 用英文"
)
# 包含 7 个核心模块 + CustomInstructions

# 场景 3: 激活技能 + 记忆系统
prompt = build_system_prompt(
    work_dir="/home/user/project",
    custom_instructions="...",
    skill_section="## Available Skills\n/review - Code review\n/test - Run tests",
    memory_section="## User Profile\n- 资深 Python 开发者\n- 偏好 pytest 测试框架"
)
# 包含全部模块
```

## 第四步：Plan 模式的特殊提示词

### Plan 模式是什么？

当用户输入 `/plan` 或任务复杂时，系统进入 Plan 模式：

```
普通模式:
  用户: "添加登录功能"
  AI: [直接开始写代码]

Plan 模式:
  用户: "添加登录功能"
  AI: [先探索代码] → [设计方案] → [写入计划文件] → [等待用户确认]
```

### Plan 模式的核心约束

```python
_PLAN_MODE_FULL_REMINDER = """\
Plan mode is active. The user indicated that they do not want you to execute yet 
-- you MUST NOT make any edits (with the exception of the plan file mentioned below), 
run any non-readonly tools (including changing configs or making commits), or 
otherwise make any changes to the system.

## Plan File Info:
{plan_file_info}
You should build your plan incrementally by writing to or editing this file. 
NOTE that this is the only file you are allowed to edit - other than this you 
are only allowed to take READ-ONLY actions.

## Plan Workflow

### Phase 1: Initial Understanding
Goal: Gain a comprehensive understanding of the user's request.
1. Focus on understanding the user's request and the code associated with their request.
2. Use the Agent tool with subagent_type="explore" to explore the codebase. 
   You can launch up to 3 explore agents IN PARALLEL.

### Phase 2: Design
Goal: Design an implementation approach.
Call the Agent tool with subagent_type="plan" to design the implementation.

### Phase 3: Review
Goal: Review the plan(s) and ensure alignment with the user's intentions.
1. Read the critical files identified by agents to deepen your understanding
2. Ensure that the plans align with the user's original request

### Phase 4: Final Plan
Goal: Write your final plan to the plan file (the only file you can edit).
- Begin with a Context section explaining why this change is being made
- Include only your recommended approach
- Include the paths of critical files to be modified
- Include a verification section describing how to test the changes

### Phase 5: Call ExitPlanMode
At the very end of your turn, call ExitPlanMode to indicate that you are done planning."""
```

### 动态提醒机制

```python
_REMINDER_INTERVAL = 5  # 每 5 轮提醒一次

def build_plan_mode_reminder(
    plan_path: str, 
    plan_exists: bool, 
    iteration: int
) -> str:
    """动态生成 Plan 模式提醒"""
    
    # 第 1 轮：完整提示
    if iteration == 1:
        return _PLAN_MODE_FULL_REMINDER.format(plan_file_info=...)
    
    # 第 6, 11, 16... 轮：再次显示完整提示
    attachment_index = (iteration - 1) // _REMINDER_INTERVAL
    if attachment_index % _REMINDER_INTERVAL == 0:
        return _PLAN_MODE_FULL_REMINDER.format(plan_file_info=...)
    
    # 第 2-5, 7-10... 轮：简化提示
    return (
        "Plan mode still active (see full instructions earlier in conversation). "
        f"Read-only except plan file ({plan_path}). Follow 5-phase workflow."
    )
```

### Plan 文件信息生成

```python
def build_plan_mode_reminder(plan_path: str, plan_exists: bool, iteration: int) -> str:
    if plan_exists:
        plan_file_info = (
            f"Plan file: {plan_path}\n"
            f"A plan file already exists at {plan_path}. "
            "You can read it and make incremental edits using the EditFile tool."
        )
    else:
        plan_file_info = (
            f"Plan file: {plan_path}\n"
            f"No plan file exists yet. You should create your plan at {plan_path} "
            "using the WriteFile tool."
        )
    
    return _PLAN_MODE_FULL_REMINDER.format(plan_file_info=plan_file_info)
```

## 第五步：环境上下文构建

### build_environment_context - 运行时信息

```python
def build_environment_context(
    work_dir: str,
    active_skills: dict[str, str] | None = None,
    skill_catalog: str = "",
    agent_catalog: str = "",
) -> str:
    """构建环境上下文信息"""
    parts = [
        f"Current working directory: {work_dir}",
        f"Operating system: {platform.system()} {platform.release()}",
        f"Current time: {datetime.now().strftime('%Y-%m-%d %H:%M:%S')}",
    ]
    
    # Agent 目录
    if agent_catalog:
        parts.append("")
        parts.append(agent_catalog)
    
    # Skill 目录
    if skill_catalog:
        parts.append("")
        parts.append(skill_catalog)
    
    # 已激活的技能详情
    if active_skills:
        parts.append("")
        parts.append("## Active Skills")
        for name, sop in active_skills.items():
            parts.append(f"\n### Skill: {name}\n")
            parts.append(sop)
    
    return "\n".join(parts)
```

### 使用场景

```python
# 场景 1: 仅基础信息
context = build_environment_context(work_dir="/home/user/project")
# 输出:
# Current working directory: /home/user/project
# Operating system: Linux 5.15.0
# Current time: 2024-03-15 14:30:00

# 场景 2: 包含技能列表
context = build_environment_context(
    work_dir="/home/user/project",
    skill_catalog="Available skills: /review, /test, /commit"
)

# 场景 3: 包含激活的技能详情
context = build_environment_context(
    work_dir="/home/user/project",
    active_skills={
        "/review": "代码审查技能，检查代码质量...",
        "/test": "测试执行技能，运行单元测试..."
    }
)
# 输出:
# Current working directory: /home/user/project
# ...
# ## Active Skills
#
# ### Skill: /review
# 代码审查技能，检查代码质量...
#
# ### Skill: /test
# 测试执行技能，运行单元测试...
```

## 代码亮点：设计模式与最佳实践

### 亮点 1: 模块化设计

```python
# ❌ 坏做法：硬编码
def build_prompt():
    return """
    You are MewCode...
    # System
    ...
    # Doing tasks
    ...
    """

# ✅ 好做法：模块化
IDENTITY_SECTION = PromptSection(name="Identity", priority=0, content="...")
SYSTEM_SECTION = PromptSection(name="System", priority=10, content="...")

builder = PromptBuilder()
builder.add(IDENTITY_SECTION)
builder.add(SYSTEM_SECTION)
```

**好处**：
- 每个模块独立维护
- 可以动态启用/禁用模块
- 易于测试

### 亮点 2: 优先级排序

```python
# 自动按优先级排序
self._sections.sort(key=lambda s: s.priority)

# 添加顺序无关
builder.add(MEMORY_SECTION)        # priority=95
builder.add(IDENTITY_SECTION)      # priority=0
builder.add(ENVIRONMENT_SECTION)   # priority=70

# 结果自动正确排序: Identity → Environment → Memory
```

**好处**：
- 不需要手动控制添加顺序
- 新增模块时只需指定优先级
- 避免顺序错误

### 亮点 3: 链式调用

```python
# 支持链式调用（返回 self）
def add(self, section: PromptSection) -> PromptBuilder:
    self._sections.append(section)
    return self  # ← 关键

# 使用
prompt = (
    PromptBuilder()
    .add(IDENTITY_SECTION)
    .add(SYSTEM_SECTION)
    .add(DOING_TASKS_SECTION)
    .build()
)
```

**好处**：
- 代码更紧凑
- 符合流式接口（Fluent Interface）模式

### 亮点 4: 条件组装

```python
def build_system_prompt(
    custom_instructions: str = "",
    skill_section: str = "",
    memory_section: str = "",
    ...
):
    b = PromptBuilder()
    b.add(IDENTITY_SECTION)  # 必选
    b.add(SYSTEM_SECTION)    # 必选
    
    # 可选模块
    if custom_instructions:
        b.add(PromptSection(name="CustomInstructions", priority=80, ...))
    
    if skill_section:
        b.add(PromptSection(name="Skills", priority=90, ...))
    
    if memory_section:
        b.add(PromptSection(name="Memory", priority=95, ...))
    
    return b.build()
```

**好处**：
- 根据运行时条件动态组装
- 不需要的模块不会出现在最终提示词中

### 亮点 6: Plan 模式的渐进提醒

```python
def build_plan_mode_reminder(plan_path: str, plan_exists: bool, iteration: int) -> str:
    # 第 1 轮：完整提示（1000+ 字符）
    if iteration == 1:
        return _PLAN_MODE_FULL_REMINDER
    
    # 第 6, 11, 16... 轮：再次完整提示
    if (iteration - 1) // 5 % 5 == 0:
        return _PLAN_MODE_FULL_REMINDER
    
    # 其他轮次：简化提示（50 字符）
    return _PLAN_MODE_SPARSE_REMINDER
```

**为什么这样设计？**

```
轮次 1: 完整提示 (1000 chars) - AI 第一次看到，需要详细说明
轮次 2-5: 简化提示 (50 chars) - AI 记得，只需要提醒
轮次 6: 完整提示 (1000 chars) - 防止遗忘，重新强调
轮次 7-10: 简化提示 (50 chars)
轮次 11: 完整提示 (1000 chars)
...
```

**好处**：
- 节省 tokens（大部分轮次用简化版）
- 防止遗忘（定期重复完整版）

## 总结

系统提示词组装管理解决了什么问题：

1. **模块化组织**：PromptSection 将提示词分成独立模块
2. **优先级控制**：自动排序，确保正确顺序
3. **动态组装**：根据运行时条件灵活组合
4. **特殊模式支持**：Plan 模式、Coordinator 模式
5. **环境感知**：动态生成工作目录、时间等信息
6. **扩展性**：Hook 注入、技能加载、记忆系统

**代码亮点**：
- ✨ **模块化设计**：每个 Section 独立维护
- ✨ **优先级排序**：添加顺序无关，自动正确排序
- ✨ **链式调用**：流式接口，代码简洁
- ✨ **条件组装**：按需启用模块
- ✨ **动态生成**：静态 + 动态内容结合
- ✨ **渐进提醒**：Plan 模式节省 tokens

核心原则：

- **单一职责**：每个模块只做一件事
- **开闭原则**：对扩展开放，对修改封闭
- **依赖倒置**：依赖抽象（PromptSection），不依赖具体实现
